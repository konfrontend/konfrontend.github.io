The Profile is the person's data and the only thing the other States know about them. It is Markdown with YAML frontmatter under `profile/`, all hand-editable and the source of truth after this wizard writes it:

- `profile.md`: facts only, empty body. Identity, constraints, the resume contact line, the resume order of the Projects, refused stacks, niche, interests, avoid list, Family precedence, word cap, terms.
- `projects/<slug>.md`: one per Project. Frontmatter is meta only (`name`, `url`, `role`, `employment`, `start`, `end`, `naming`, `domain`, `description`, `keywords`); the body holds the Stories under bold Themes: one list item per Story, `- [key] Bullet`, with the Facts behind it as indented context lines. The key is lowercase, hyphenated, unique within the Project, and stable: a Version selects Stories by it. `keywords` names the canonical Skills the Project proves, one spelling everywhere; the Skills of the Profile are the union of every Project's `keywords`, nothing else declares them. Every claim in a Letter must trace to a Story or a frontmatter field.
- `voice.md`: every Letter-facing personal string: `language`, `greeting` per route (`freelance`, `employment`), `sign_off`, `banned_extra`, `allowed_extra`, `cite_role_period`. No body: the schema forbids one, and the Answers in `answers/` calibrate the voice.
- `answers/<slug>.md`: one hand-written Answer per recurring question, `question` in the frontmatter, the Answer as the body.

`master.md` and `skills.md` beside them are generated by `npm run build -w profile` at the project root (the Master with every Story, the Skill ledger with Seen counts and Gaps from the Candidates' `requirements`); never write them by hand.

Schemas with inline defaults: `profile/schemas/profile.schema.json`, `project.schema.json`, `voice.schema.json`. `node ${CLAUDE_PLUGIN_ROOT}/scripts/profile.ts skeleton <profile|voice|project>` prints a YAML skeleton with the defaults filled and every required field and enum marked; draft from it, never from memory. Every write under `profile/` is validated by a hook against its schema; on mismatch the hook returns the error list: fix the frontmatter and write again.

Pasted sources are input only. Extract, then drop them; nothing under `profile/` keeps a resume or an Upwork profile text. The skills work from the Profile alone.

## Steps

1. **Permissions.** The plugin cannot ship permission rules, so the project's `.claude/settings.json` holds them. Read that file (missing counts as empty) and list which of these `permissions.allow` rules it lacks:
   ```
   Bash(node */scripts/*.ts *)
   Edit(profile/**)
   Edit(private/**)
   ```
   None missing: say so in one line. Otherwise show the missing ones and ask once whether to add them; on yes, merge them into `permissions.allow`, keeping every other key and rule. On no, go on: the Route still works, with a permission prompt on each script call and write. Done when the human has answered or nothing is missing.
2. **Sources.** The argument or the next message carries pasted text or file paths: Upwork profile, resume, past Letters, anything with facts about the person. Read every file path given. Done when at least one source is in hand.
3. **Draft.** Print the skeletons and fill them from the sources:
   - `profile.md`: `identity.constraints` holds facts a Job can fail on (location, nationality, work permit, working arrangement). `contact` is the resume contact line. `resume_order` lists every Project slug, most relevant first. `terms` numbers come from the sources or stay at the placeholder until step 4.
   - one `projects/<slug>.md` per Project found, slug from the product name, two to three words, lowercase, hyphenated. `naming` is `public` when the product is named and linkable, `first-name-only` or `nda` otherwise. Frontmatter from the sources; `start` and `end` as `YYYY-MM`, no `end` while ongoing. Stories: every concrete thing done there, one list item each under a Theme, with a key of one to three words, numbers only when the source states them. `keywords`: every technology or domain practice the Project shows in production, by one canonical spelling shared across Projects (never years of experience or a spoken language).
   - `voice.md`: `sign_off` is the first name, `greeting.freelance`, `greeting.employment` and `language` from the defaults unless a past Letter shows otherwise.
   Done when every field the sources answer is filled and every required field they leave empty is listed.
4. **Gaps.** Ask the human for the required fields still empty, in one message, grouped per file, with the choices for enum fields and the catalogue default named where one exists (`family_precedence`, `word_cap`, `billing`). Ask nothing the sources already answered and nothing optional. Done when every required field has a value.
5. **Summary and write.** Show one block per file: the frontmatter as it will be written and, for a Project, its Stories. Then write each file with the Write tool, `profile.md` and `voice.md` first, then `projects/<slug>.md` one by one. Create the folders when missing. A rejected write names the errors: fix them and write again. Then run `npm run build -w profile` at the project root. Done when `node ${CLAUDE_PLUGIN_ROOT}/scripts/profile.ts status` reports both gates as `pass`.
6. **Report.** Print the status output and the next command: `/autotriage:route` with a Job pasted.

## Re-run

The guard line above prints which files exist and validate. When any file exists, this is a refresh, per file:

- An invalid file: show its errors, propose the corrected frontmatter, write on confirmation.
- A valid file with new sources: draft the changed fields only, show old and new values side by side, write on confirmation. A field the human edited by hand is never overwritten without that confirmation. A Story's key never changes: a Version may select it.
- A Project in the sources with no `projects/<slug>.md` yet: draft it as in step 3 and add its slug to `resume_order`.
- A file the sources say nothing about: leave it.
