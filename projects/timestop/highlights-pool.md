# [Time Stop](https://github.com/konfrontend/timestop)

Author & Sole Full-stack Developer | Aug 2026 – Present

Local-first time tracker app with an optional self-hosted sync server.

## Product and stack

- **A** Owned the product end to end as sole author: competitor and pattern research, a glossary and data rules settled before any code, a UX prototype comparing three desktop shell layouts with the winner composed into a single-window design, then the shipped Electron app, sync server and release pipeline, through two tagged public releases under an MIT license.
- **A** Decided the stack in an architecture decision record and built it: TypeScript throughout, React with shadcn/ui in the Electron renderer, one domain package of Zod entities and rules shared by the desktop and the server, Drizzle ORM over SQLite on the desktop and PostgreSQL on the server, Hono on Node.js for the server, in an npm workspaces and Turborepo monorepo.
- **A** Designed a contract-first API: each method is a descriptor holding its Zod input schema and its output type, grouped by domain concept, and one mapped type derives the interface, so the Electron IPC handlers, the preload bridge, the SQLite implementation and the renderer test harness all walk the same object and a missing member fails typecheck.
- **A** Built a deterministic agentic workflow by fixing the domain before the code, so AI coding agents and author worked from one vocabulary and one set of rules: a glossary whose words every identifier in the code uses, a document of entity rules, five design decisions settled as tickets before the first line of app code, and an architecture decision record for every stack and data choice since, which is what carried 70 pull requests to master in five weeks as a sole developer.
- **A** Decoupled the brand from the implementation: the product name is also a storage identity, naming the user-data folder, the installer's app id and the database file, so a rename would strand every install. The name now lives in one source that the main process, the renderer and the end-to-end tests import, a lint script fails on the name anywhere outside a short allowlist, and that allowlist doubles as the rename checklist.
- **A** Designed the local-first model: the desktop SQLite database is the source of truth, every write stores its entity row and an append-only change log entry in one transaction, and the server only mirrors what it receives, one way, behind an API contract that is independent of the transport.
- **B** Decided that money is derived, in an architecture decision record: a record stores no rate, so rate, billable status and amount come from its project and workspace on read, a rate change re-prices past records, and the exported CSV stays the frozen record of what was billed.
- **C** Built a Toggl Track CSV import that maps clients, projects and entries onto the app's entities, infers the hourly rate from the export, writes a change log entry per imported entity so the history syncs like any other data, and imports the same file twice without duplicates.
- **C** Kept design tokens as CSS variables, with data-slot hooks on the app's own components as on the shadcn/ui primitives, for a later skin engine.

## Desktop app

- **A** Built the cross-platform Electron desktop app in React with TanStack Router and TanStack Query, shipping a macOS Apple Silicon disk image and a Windows per-user installer: a compact Tracker that can stay always on top, a Dashboard and Settings as routes of one window, light and dark themes following the OS, and a window size that survives relaunch.
- **A** Built the shell integration that keeps the timer reachable with the window closed: a system tray with a live elapsed-time line and glyphs drawn for the taskbar's own theme, a global hotkey, a Dock badge on macOS and a taskbar overlay on Windows, an elapsed-time window title, a single-instance lock that raises the running window, and a stop written on quit, logoff or shutdown so a timer never outlives its session.
- **B** Isolated the renderer from the shell: the Electron main process owns SQLite and the domain behind the API contract and exposes it over Zod-validated IPC with context isolation and the sandbox on, so the renderer never touches a Node or Electron API.
- **B** Made upgrades safe for the user's data: migrations run on open, a database written by a newer version is refused with a dialog and left untouched, a whole-file backup that folds in the write-ahead log is taken before any pending migration with the three newest kept, uninstalling keeps the database, and the app checks GitHub Releases on launch and offers a newer version while staying silent on any failure.
- **B** Built the Dashboard on TanStack Table: filters, batch selection, inline edits of name and start and stop times, live rounding to 15 or 30 minutes, period and time pickers, view state kept in the URL, totals per currency, and a CSV report export written with a byte order mark and CRLF line endings so Excel on Windows reads it correctly.
- **B** Tested the desktop app at its seams: Vitest for main and renderer over a harness that builds every API member from the contract so none can be left unstubbed, backed by a real in-memory SQLite with a settable clock; Playwright driving Electron end to end in a headless mode that exposes the tray and taskbar state the renderer cannot see; and a smoke test that launches the packaged Windows executable.

## Self-hosted server and sync

- **A** Built the optional self-hosted sync server in Hono on Node.js with PostgreSQL: one authenticated REST endpoint ingests batches of change log entries, stores each once by id and materializes the entity tables in the same transaction with whole-entity last-write-wins, so replaying a batch changes nothing.
- **A** Designed the push protocol on both ends: the desktop pusher sends unsent changes in insertion order in batches after every commit and on launch, retries network errors with exponential backoff from one second to five minutes until they land, and halts on a rejected token or a malformed batch while changes keep queueing locally, with the sync status shown in the Tracker and in Settings.
- **A** Shipped the server as a multi-stage Docker image for amd64 and arm64 on GitHub Container Registry, migrating on boot behind a health check, with a Docker Compose stack of PostgreSQL and a Cloudflare Tunnel so the VPS publishes no ports, ran it on a Hetzner VPS, and wrote the self-hosting guide: firewall, tunnel, secrets, tokens, upgrade, rotation, backup and a troubleshooting table that maps what the app shows to its cause.
- **B** Designed token authentication without accounts or sessions: a CLI mints a token shown once and stores only its SHA-256 hash, the first push binds the token to that install and actor under a row lock, every later push from another pair is refused, revocation runs from the same CLI, and rotation is a mint and a revoke.
- **B** Tested the server against a real PostgreSQL, a service container in CI and Testcontainers locally with one database per test file, including an integration test that drives the real desktop pusher over SQLite against the real Hono app in-process and checks that a replay changes nothing.

## Database architecture

- **A** Designed a two-dialect database layer in Drizzle ORM, SQLite on the desktop and PostgreSQL on the server, with the shared domain as the source of truth and two drift catchers: each table's inferred row type is asserted strictly equal to its Zod entity at compile time, and a test diffs the two dialects' drizzle-kit snapshots table by table, failing on any column, index or foreign key difference not listed in an allowlist with its reason, and on any allowlist entry that no longer applies.
- **A** Decided on two hand-written schemas over PostgreSQL on both sides after measuring PGlite at about 1.3 GB of resident memory against about 52 MB for better-sqlite3 on the same data, with a 150 MB budget set for an app that sits in the tray all day; also rejected a dialect-neutral table DSL and deriving the entities from the schema, and recorded every option in an architecture decision record.
- **B** Stored timestamps as fixed-width ISO 8601 UTC text so byte order is chronological and range queries stay string comparisons, pinned with a C collation on PostgreSQL, left foreign keys out of PostgreSQL on purpose because the server materializes a replay log in push order while SQLite enforces integrity where writes originate, and stamped change ids as UUIDv7 from the entity's update time.
