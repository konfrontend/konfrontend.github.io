## The repo

The professional profile of Konstantin Dolbilov, web developer, and the two things made from it: resumes and the triage of Jobs. The Profile is the source of truth; a Version and a Letter derive from it, never the other way round. `GLOSSARY.md` names the terms; `AGENTS.md` holds the rules an agent follows and points at `docs/` by topic.

## Folders

- `profile/`: the Profile, authored by hand. `profile.md` (identity, contact, resume order, `terms`), `voice.md`, `answers/<slug>.md`, `projects/<slug>.md` (one Project file each: meta frontmatter with the canonical `keywords`, then `## Overview`, the person's free prose, `## Bullets`, the canonical Bullets, `## Notes`). `schemas/` holds the JSON Schemas. `skills.md` is generated by `npm run build`, committed, read by nothing. `lib/` is the one Profile reader and the Profile check.
- `resume/`: `versions/general.md`, the one stored Version, the Markdown twin of the public PDF; `scripts/` generates, refreshes, cuts and renders a Version. The public resume, `Konstantin_Dolbilov_Resume.pdf`, and `index.html` stay at the root for GitHub Pages.
- `autotriage/`: `catalogue/` (Flags, voice, Checks, Letter templates, the Candidate contract), `scripts/` (Guard, Verdict, the State scripts, the hooks, the Tracker, the Gap print, tests), `schemas/` (the Candidate schemas). It reads the Profile through `profile/lib/` and writes only Candidates.
- `private/`: gitignored. `candidates/<YYYY-MM-DD-slug>/` holds the Candidates: `job.md`, `letter.md`, `version.md` when the Version was tailored, the PDF sent on the employment route, written by `resume-pdf`; `candidates/archive/` the desk Candidates, read by nothing.
- `docs/`: one file per topic (`format-rules.md`, what a rendered Version follows; `agents/`, how agent skills use this repo).
- `.claude/skills/`: `route` and its States `route-intake`, `route-triage`, `route-version`, `route-proposal`, `route-verify`; `tracker` and `gaps`; `resume-version` and `resume-pdf`; `pp-bullets`, which drafts a Project's Bullets from its Work repository. A skill's `refs/` holds what only that skill follows. `.claude/settings.json` registers the hooks, always on, and the permission allow list.

## Commands

- `npm test`: every `*.test.ts`, then `tsc --noEmit`.
- `npm run build`: the Profile check, then `profile/skills.md`; run after a Profile edit and commit the result.
- `resume-version [<Candidate folder>]`: makes the general Version, or a Candidate's tailored one. `resume-pdf [<Candidate folder> | <Version path>]`: renders the PDF sent into a Candidate folder, or a Version beside itself (the general one to the root PDF), every check PASS, one A4 page.

## Workflow for an application

`/route` with the posting pasted: intake, triage, the checkpoint (the person answers go or no-go and the Verdict is written), `route-version` on the employment route (general, or `resume-version` writes `version.md`), proposal, verify. Then `resume-pdf` on the Candidate folder. `/tracker` prints where every Candidate stands; `/gaps` prints the Gaps and the Skills seen.
