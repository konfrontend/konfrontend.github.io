# State machines for deterministic skills: what the docs say

Research notes, 2026-10-18. Primary sources only (official docs, package registries, package sources, the anthropics/claude-code repository). Local observations are marked as such. Findings only; no fix proposals.

## Short answers

1. **Fits for a file-backed, human-in-the-loop, resumable Route.** XState v5 runs without a server, has no runtime dependencies, persists an actor as JSON (`getPersistedSnapshot()` / `createActor(logic, { snapshot })`) and exposes pure `transition()` / `initialTransition()` functions; guards must be pure and synchronous. A hand-rolled table is TypeScript's documented discriminated-union plus `never` exhaustiveness pattern, with no library. Effect 4 ships a `workflow` export whose every module is marked `@stability unstable`; the only engine found in the package is in-memory. Temporal needs a running Temporal Service and a Worker, and its Workflow code runs in a deterministic sandbox. `node:sqlite` is a release candidate from Node 24.15.0 and warns on the local 24.14.0.
2. **Zero bundling in a plugin.** Hook commands run through `sh -c` (shell form) or an executable resolved on `PATH` (exec form), in Claude Code's environment; the docs name no Node version and say the native binary does not invoke Node. A marketplace plugin copied into the cache gets its npm dependencies installed automatically when `package.json` sits beside a `package-lock.json`; a plugin loaded in place does not. Compiled JS is not documented either way; the docs' own example runs `node ${CLAUDE_PLUGIN_ROOT}/scripts/format.js`. Node runs `.ts` files directly since 22.6.0 (default since 23.6.0 / 22.18.0, stable since 24.12.0), erasable syntax only.
3. **Known examples.** Three plugins in anthropics/claude-code use hooks: `ralph-wiggum` (bash Stop hook, state in a Markdown file with YAML frontmatter), `hookify` (python3 PreToolUse/PostToolUse/Stop/UserPromptSubmit rules read from `.local.md` files), `security-guidance` (python, SessionStart installs its SDK on first run). None models a multi-State workflow with per-State guards. No Anthropic engineering post on the topic was found.
4. **Node version Claude Code requires.** None for the native, Homebrew, WinGet and Linux-package installs. The npm package wants Node 22 or later, but "the package downloads a native binary that doesn't use your Node.js at runtime".

## Evidence

### Q1 State-machine approaches

**XState v5** (https://stately.ai/docs/xstate, https://stately.ai/docs/persistence, https://stately.ai/docs/guards, https://stately.ai/docs/transitions, https://stately.ai/docs/typescript, https://stately.ai/docs/testing; all undated)

- Install: `npm install xstate`. Registry `xstate@5.33.3` (modified 2026-10-17) has no `dependencies`, `peerDependencies` or `engines` field; `dist/xstate.esm.js` is 17,848 bytes on unpkg (measured 2026-10-18); `dist.unpackedSize` 2,313,880 bytes including types and maps.
- Persistence: `const persistedState = feedbackActor.getPersistedSnapshot();` stored via `JSON.stringify`; restore with `createActor(behavior, { snapshot: restoredState }).start()`. "the state must be serializable, which means that it must be JSON-serializable." On restore: "Actions from machine actors will not be re-executed, because they are assumed to have been already executed." and "invocations will be restarted, and spawned actors will be restored recursively." The page offers event sourcing as the alternative: "Event sourcing can be more reliable than persisting state".
- Guards: "A **guard** is a condition function that the machine checks when it goes through an event." Forms: `guard: 'isValid'`, inline `guard: ({ context, event }) => true`, object `{ type: 'isValid', params: { maxLength: 50 } }`. "Guards should be pure, synchronous functions that return either `true` or `false`." Composed with `and([...])`, `or([...])`, `not(...)`; `stateIn(stateValue)` checks the whole machine's state. Typed via `setup({ guards: { … } })`.
- Determinism: "Transitions are "deterministic"; each combination of state and event always points to the same next state." The transitions page names "the pure `transition(machine, state, event)` and `initialTransition(machine)` functions" and recommends them over `getNextSnapshot(...)`. The shipped typings (`dist/declarations/src/transition.d.ts`, unpkg) read: `export declare function transition<T extends AnyActorLogic>(logic: T, snapshot: SnapshotFrom<T>, event: EventFromLogic<T>): [nextSnapshot: SnapshotFrom<T>, actions: ExecutableActionsFrom<T>[]];` with the comment "This is a pure function that does not execute `actions`."
- Typed artifacts: "The recommended way to strongly type your machine is to use the `setup(...)` function:" with `context: {} as { count: number }` and `events: {} as { type: 'inc' } | { type: 'dec' }`. "XState v5 requires TypeScript version 5.0 or greater." `strictNullChecks` strongly recommended. Per-State artifact types are not a documented concept; context is one type for the whole machine.
- Testing: the testing page documents only actor-based tests ("Arrange, Act, Assert" with `createActor`, `actor.start()`, `actor.send`, `actor.getSnapshot().value`); "The XState Test model-based testing utilities have moved into `xstate` itself and are now available under `xstate/graph`." Testing guards in isolation is not documented.
- Server: none required; nothing on the pages mentions one.

**Hand-rolled typed transition table** (https://www.typescriptlang.org/docs/handbook/2/narrowing.html, undated)

- "When every type in a union contains a common property with literal types, TypeScript considers that to be a _discriminated union_, and can narrow out the members of the union."
- Exhaustiveness: "you can use narrowing and rely on `never` turning up to do exhaustive checking in a `switch` statement." Adding a union member makes `const _exhaustiveCheck: never = shape;` fail with `Type 'Triangle' is not assignable to type 'never'.`
- Persistence, guards, resumption, footprint: whatever the author writes; no library, no dependency, no server. Nothing further is documented because nothing further exists.

**Effect** (https://effect.website/docs/, registry and unpkg for `effect@4.0.5`, https://github.com/Effect-TS/effect-smol)

- The docs landing page says "Effect 4.0 is here" and "Effect is a single dependency with zero required tooling." It has no page or navigation entry for workflow, cluster, durable or unstable; the `effect/unstable` namespace is not mentioned.
- Registry `effect@4.0.5` (modified 2026-10-16): no `dependencies`; `dist.unpackedSize` 51,489,523 bytes; `exports` include `"./workflow": "./dist/workflow/index.js"` and `"./cluster"`.
- `dist/workflow/index.d.ts` marks each module `@stability unstable` / `@since 4.0.0`: `Activity`, `DurableClock`, `DurableDeferred`, `DurableQueue`, `Workflow`. `Workflow.d.ts` requires a `WorkflowEngine` service for `execute`, `poll`, `interrupt`, `resume`. `WorkflowEngine.d.ts` declares `export declare const layerMemory: Layer.Layer<WorkflowEngine>;`. A persistent engine is not in the `workflow` export; the `cluster` export was not read. The effect-smol repository has `packages/effect/src/unstable/workflow`.
- Effect 3 line: `@effect/workflow@0.19.1` (peers `effect ^3.22.1`, `@effect/rpc`, `@effect/platform`, `@effect/experimental`) and `@effect/cluster@0.60.2` (peers add `@effect/sql`, `@effect/workflow`; dependency `kubernetes-types`). `https://www.npmjs.com/package/@effect/workflow` returned 403 and `github.com/Effect-TS/effect/tree/main/packages/workflow` 404 to fetch tools.
- Guards, per-State artifact types, resumption across sessions without a server: not documented in anything read.

**Temporal TypeScript SDK** (https://docs.temporal.io/develop/typescript/set-up-your-local-typescript, https://docs.temporal.io/develop/typescript/workflows/basics, https://docs.temporal.io/workflows; undated)

- "The TypeScript SDK requires Node.js 20 or later." Install: `npm install @temporalio/client @temporalio/worker @temporalio/workflow`. Registry 1.24.0: `engines.node ">= 20.3.0"`; `@temporalio/worker` lists 20 dependencies including `webpack`, `@swc/core`, `@grpc/grpc-js`, `protobufjs`.
- Server: install the Temporal CLI, run `temporal server start-dev`; "Leave the local Temporal Service running as you work through tutorials and other projects." The dev server uses an "in-memory database".
- Determinism: "In the Temporal TypeScript SDK, Workflows run in a deterministic sandboxed environment." "The Workflow sandbox can run only deterministic code, so side effects and access to external state must be done through Activities". `Math.random()`, `Date`, `setTimeout()` "are replaced by deterministic versions". Persistence: "Temporal keeps the Event History." "This history is the source of truth for everything that happens in the Workflow." "It has to make the same decisions when given the same history."
- Guards as a concept: not documented; branching is plain code inside the Workflow.

**`node:sqlite`** (https://nodejs.org/docs/latest-v22.x/api/sqlite.html, https://nodejs.org/docs/latest-v24.x/api/sqlite.html, https://nodejs.org/docs/latest-v25.x/api/sqlite.html, https://nodejs.org/docs/latest-v24.x/api/cli.html, https://nodejs.org/docs/latest-v24.x/api/process.html)

- History: "Added in: v22.5.0"; "v23.4.0, v22.13.0: SQLite is no longer behind `--experimental-sqlite` but still experimental."; "v24.15.0: SQLite is now a release candidate." (also "v25.7.0"). Stability in v24/v25 docs: "Stability: 1.2 - Release candidate."; v22 docs still say "Stability: 1.1 - Active development."
- Local observation, Node 24.14.0: `import('node:sqlite')` prints `(node:97074) ExperimentalWarning: SQLite is an experimental feature and might change at any time`. The docs page itself contains no warning text.
- API: "This module is only available under the `node:` scheme." `new DatabaseSync(path[, options])` (`':memory:'` allowed; `defensive` on by default since v24.14.0); `database.exec(sql)`; `database.prepare(sql[, options])` returns `StatementSync`; `statement.run(...)` returns `{ changes, lastInsertRowid }`; `statement.get(...)`; `statement.all(...)`. `database.isTransaction` (added v24.0.0) "is a wrapper around `sqlite3_get_autocommit()`". No transaction helper is documented; transactions are SQL through `exec`.
- Silencing: `--no-warnings`: "Silence all process warnings (including deprecations)." `--disable-warning=code-or-type` (added v21.3.0, v20.11.0; "v24.20.0: The `--disable-warning` flag is now stable."): "The Node.js core warning types are: `DeprecationWarning` and `ExperimentalWarning`", with the example `node --disable-warning=ExperimentalWarning`. `NODE_NO_WARNINGS=1`: "When set to `1`, process warnings are silenced." `NODE_OPTIONS` allows `--disable-warning` and `--no-warnings`. Process docs: "By default, Node.js will print process warnings to `stderr`. The `--no-warnings` command-line option can be used to suppress the default console output but the `'warning'` event will still be emitted". `process.removeAllListeners('warning')` is not documented as a silencing method; locally it silenced the warning on 24.14.0 (observed, undocumented). All four variants printed nothing locally.
- Guards: SQL constraints plus JS; typed artifacts: rows, typed by the author; no server; no dependency.

### Q2 What runs with zero bundling in a plugin

**Hook execution** (https://code.claude.com/docs/en/hooks, https://code.claude.com/docs/en/plugins/manifest-reference, https://code.claude.com/docs/en/plugins/components; undated)

- "**Shell form** runs when `args` is absent. The `command` string is passed to a shell: `sh -c` on macOS and Linux, Git Bash on Windows, or PowerShell when Git Bash isn't installed." "**Exec form** runs when `args` is present. Claude Code resolves `command` as an executable on `PATH` and spawns it directly with `args` as the argument vector." "Handlers run in the current directory with Claude Code's environment." `CLAUDE_PROJECT_DIR`, `CLAUDE_PLUGIN_ROOT`, `CLAUDE_PLUGIN_DATA` are exported to the process.
- Input on stdin as JSON (`session_id`, `cwd`, `hook_event_name`, `tool_name`, `tool_input`, ...). Exit codes: 0 success, JSON on stdout for structured control; "Exit with code 2 to block the action." "Exit code 1 without valid JSON output is a non-blocking error... If your hook is meant to enforce a policy, use `exit 2`." PreToolUse JSON: `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"..."}}`; decisions "(allow/deny/ask/defer)". Timeout default 600 s for command hooks.
- Skill tool: the PreToolUse `tool_input` tables cover "Bash, PowerShell, Edit, Write, Read, Glob, Grep, Agent, Workflow, WebFetch, WebSearch, AskUserQuestion, and ExitPlanMode"; no Skill entry. "a `PreToolUse` hook matching the `Skill` tool fires only when Claude calls the tool, but typing `/skillname` directly bypasses `PreToolUse`. `UserPromptExpansion` fires on that direct path."
- Runtime: no sentence names a Node version or a bundled runtime for hooks. Examples use `"command": "node", "args": ["${CLAUDE_PLUGIN_ROOT}/scripts/format.js", "--fix"]`; on Windows, `.cmd` shims in `node_modules/.bin` cannot be spawned in exec form, so "invoke the underlying script with `node` directly". Compiled JS: not documented.
- `${CLAUDE_PLUGIN_ROOT}`: "Absolute path of the plugin's installed version"; "changes when the plugin updates, so don't write state there." `${CLAUDE_PLUGIN_DATA}`: "`~/.claude/plugins/data/<id>/`, created on first reference and kept across plugin updates", for "Installed dependencies such as `node_modules`, generated code, and caches". Standard layout lists `scripts/` as a convention: "The name `scripts/` is a convention, not something Claude Code looks for".

**Dependencies** (https://code.claude.com/docs/en/plugins/loading, undated)

- "When Claude Code copies a plugin into the cache, it also installs the plugin's Node.js package dependencies there, so the plugin's hooks and MCP servers can load them." Runs on install, update, and "At session start when an enabled plugin isn't cached yet". "The install runs only when the plugin's root directory contains both a `package.json` and a supported lockfile." Lockfiles: `bun.lock`, `npm-shrinkwrap.json`, `package-lock.json` (`lockfileVersion` 2 or 3); `yarn.lock` and `pnpm-lock.yaml` are skipped. "Claude Code runs the matched lockfile's package manager from the user's PATH".
- Limits: "Registry packages only", exact pins, "`--ignore-scripts`", "60-second timeout", no `overrides`. "You can't turn the automatic install off."
- Not for in-place plugins: "For a relative-path plugin loaded in place from a marketplace you added from a local path, Claude Code doesn't install the dependencies into the source directory. Install them there yourself, or from a hook into `${CLAUDE_PLUGIN_DATA}`." `--plugin-dir` plugins load "in place and is never copied". Hooks docs pattern: "a hook or skill that tests for `${CLAUDE_PLUGIN_DATA}/node_modules` and runs `npm install` if absent."

**`!` injection in SKILL.md** (https://code.claude.com/docs/en/skills, undated)

- Runs before the skill content reaches Claude; default shell `bash`, "stderr is merged into stdout"; session cwd; "2-minute default timeout". "A non-zero exit aborts the entire skill invocation, and Claude never sees the skill content." "Append `|| true` to commands you expect to exit non-zero." Injected commands don't prompt; a deny rule aborts; `"disableSkillShellExecution": true` replaces them with `[shell command execution disabled by policy]`. Skills "can bundle and run scripts in any language."

**Node running TypeScript** (https://nodejs.org/docs/latest-v24.x/api/typescript.html)

- "Stability: 2 - Stable". History: "v22.6.0: Added"; "v23.6.0: Type stripping is enabled by default." (cli.html adds v22.18.0); "v24.3.0: Type stripping no longer emits an experimental warning."; "v24.12.0: Type stripping is now stable." Only inline types are removed; `enum`, `namespace` with runtime code, parameter properties and import aliases need `--experimental-transform-types` ("Stability: 1.2 - Release candidate"); decorators "will result in a parser error". Disable with `--no-strip-types`.

**esbuild and tsup** (https://esbuild.github.io/api/, https://esbuild.github.io/content-types/, https://raw.githubusercontent.com/egoist/tsup/main/docs/README.md)

- esbuild: "To bundle a file means to inline any imported dependencies into the file itself." Bundling is off by default. `--format=esm`; `--platform=node` defaults the format to `cjs`. `--packages=external`: "all package imports considered external to the bundle, and are not bundled" and "your dependencies must still be present on the file system when your bundle is run"; the default `bundle` "means that package imports are allowed to be bundled". `--external` accepts `*` wildcards. "esbuild _does not_ do any type checking so you will still need to run `tsc -noEmit`"; enable `isolatedModules`; `emitDecoratorMetadata` and `.d.ts` generation unsupported. Registry 0.28.2: `engines.node ">=18"`, 147 KB unpacked plus a platform binary.
- tsup: "Bundle your TypeScript library with no config, powered by esbuild"; "dependencies and peerDependencies in your package.json are always excluded"; `noExternal` re-includes them; `--format` supports `esm, cjs, (default) and iife`; `--target` "defaults to compilerOptions.target in your tsconfig.json, or node14 if unspecified". Registry 9.0.0: 17 dependencies (incl. `rollup`, `esbuild`); `engines.node "^22.18.0 || ^24.11.0 || >=26.0.0"`.

### Q3 Known hook-guarded workflow examples

- `plugins/ralph-wiggum` (https://github.com/anthropics/claude-code/tree/main/plugins/ralph-wiggum): one `Stop` command hook, `hooks/stop-hook.sh` (bash, `jq`, `perl`). State file `.claude/ralph-loop.local.md`, written by `scripts/setup-ralph-loop.sh` with YAML frontmatter `iteration`, `max_iterations`, `completion_promise`; the hook parses it with `sed`/`grep`, validates numbers, deletes the file and exits 0 to end the loop. The hooks guide adds: "Claude Code overrides a Stop hook after it blocks eight times in a row with no tool call from Claude in between"; check `stop_hook_active`; raise with `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` (https://code.claude.com/docs/en/hooks-guide).
- `plugins/hookify`: `PreToolUse`, `PostToolUse`, `Stop`, `UserPromptSubmit` hooks, each `python3 ${CLAUDE_PLUGIN_ROOT}/hooks/<event>.py` with `timeout: 10`; rules are `.claude/hookify.<name>.local.md` files with YAML frontmatter; "Rules take effect on the very next tool use."
- `plugins/security-guidance`: python hooks; `SessionStart` runs `ensure_agent_sdk.py` with `timeout: 180` (dependency install at first run); `PostToolUse` entries use `"if": "Bash(git commit:*)"` and `asyncRewake`; prerequisites "Claude Code CLI ≥ v2.1.144" and "Python 3.8+ on `PATH`".
- No hooks directory in `feature-dev`, `code-review`, `pr-review-toolkit`, `commit-commands`, `plugin-dev`, `agent-sdk-dev`. anthropics/skills holds `skills/`, `spec/`, `template/` and no plugin hooks.
- Docs: the hooks guide's worked examples are notification, auto-format, "Block edits to protected files", re-inject context, audit config changes, reload environment, auto-approve prompts; none sequences States. The hooks reference opens with: hooks give "deterministic control: certain actions always happen rather than relying on the LLM to choose to run them."
- Dynamic workflows (https://code.claude.com/docs/en/workflows): "A workflow script holds the loop, the branching, and the intermediate results itself"; `Date.now()`, `Math.random()` and `new Date()` throw inside the script; a stopped run is "Resumable in the same session" and completed agents return saved results on relaunch. Constraints: "No mid-run user input", "No direct filesystem or shell access from the workflow itself", "No module loading: a script that contains `import()` fails before the run starts". Distributed from a plugin's `workflows/` directory as `/<plugin>:<meta.name>`.
- Anthropic engineering post on hook-gated workflows: none found (search 2026-10-18).

### Q4 Node version Claude Code requires

- https://code.claude.com/docs/en/setup (undated): system requirements list OS, 4 GB RAM, network, shell, location, `ripgrep`; no Node. "The npm package requires Node.js 22 or later." On older Node "the install completes and `claude` still runs, since the package downloads a native binary that doesn't use your Node.js at runtime." "The installed `claude` binary does not itself invoke Node." Hook and injected-command scripts therefore run on whatever `node` the user's `PATH` provides; a version for that is not documented.

## Confidence and gaps

- High: Claude Code hook execution model, dependency auto-install rules and its in-place exception, `!` abort semantics, Node type-stripping and `node:sqlite` histories, XState persistence and pure `transition` signature (read from the shipped `.d.ts`), Temporal's server and sandbox requirements, esbuild `--packages=external` text.
- XState bundle size is a byte count of one dist file on unpkg, not a documented figure; the docs state no size.
- Effect: the docs site has no workflow page; stability comes from `@stability unstable` tags in the shipped typings. Whether a persistent `WorkflowEngine` exists in `effect/cluster` was not read. npm and GitHub pages for `@effect/workflow` blocked fetch tools.
- `process.removeAllListeners('warning')` silencing is a local observation only; the process docs document `--no-warnings`, `--disable-warning` and `NODE_NO_WARNINGS`.
- The hooks reference was read in three slices; the PreToolUse tool list and the Skill-bypass sentence come from the middle slice. tsup docs were read from the GitHub README, not the rendered site, which returned only its title.
- `node:sqlite` is "release candidate" from 24.15.0; the local 24.14.0 still prints the ExperimentalWarning.

## What this means for autotriage

- Guards already are a hand-rolled table: `guard.mjs` is a `switch` over State names with file reads as conditions. The documented upgrade is types, not a library: a discriminated union of States and `never` exhaustiveness cost no dependency; XState adds pure `transition()` and JSON snapshots but models one context for the whole machine, not one artifact type per State, and its guards must be synchronous and pure, which rules out `fs` reads inside them unless the files are read first and passed as context.
- Persistence stays where it is in every option but SQLite: XState snapshots and the hand-rolled table both serialize to a file; `node:sqlite` would move State out of the Markdown frontmatter the human edits by hand, at the price of an ExperimentalWarning on Node < 24.15 that `--disable-warning=ExperimentalWarning` or `NODE_NO_WARNINGS=1` silences.
- Effect 4 workflow and Temporal are durable-execution engines for long-running processes: Temporal needs a Temporal Service and a Worker; Effect's shipped engine is in-memory and the whole module is tagged unstable. Neither adds determinism the guard script lacks; both add a runtime the plugin cannot run inside a hook without an install step.
- The vendored bundle can go two ways: a `package-lock.json` beside `package.json` makes Claude Code install `yaml` and `ajv` for marketplace installs, but not for `--plugin-dir` or local-path marketplaces, where a `SessionStart` hook into `${CLAUDE_PLUGIN_DATA}` is the documented fallback; or the scripts drop `yaml`/`ajv` so nothing needs installing. TypeScript source runs on Node ≥ 22.18 / 23.6 unbundled, erasable syntax only, and with no `enum`.
- The `!` guard line and the PreToolUse hook are the only gates; typing `/autotriage:<state>` bypasses PreToolUse, and a non-zero `!` exit aborts the invocation and hides the whole SKILL.md; whether the refusal line the Route SKILL expects to "print verbatim" reaches the model or the human on that path is not documented.
