# Format rules

Rules for a rendered Version: `resume/versions/general.md` and a tailored Version at `private/candidates/<folder>/version.md`, beside the employment Candidate's `job.md` and `cover-letter.md`. The Master is not rendered. Layout (fonts, sizes, margins, spacing, single column) is fixed by `resume/renderer/resume.css`; the Version's shape, a selection over the Profile, is described in the `resume-pdf` skill and `profile/schemas/version.schema.json`. Adopted from upstream `resume-formatter`, which is not installed.

- Sections, in order: summary, Skills, Professional Experience, Projects. The name, the Version's `title` as the headline, the contact line and the summary carry no header. Skills holds the Version's hand-grouped lines; every term is a canonical Skill, spelled as the Project file's `keywords` spell it, abbreviation included when the name carries one (`Role-based access control (RBAC)`). Professional Experience holds the selected Projects whose `employment` is not `independent`; Projects holds the rest. No Education section. Header names come from the ATS-recognized set only.
- Contact line, from `profile/profile.md` `contact`: location with UTC offset, email, GitHub, LinkedIn. No phone, no photo, no street address.
- Entry heading: `[Name](url) – description` and a role row `Role (Contract) | Mar 2019 – Present`, derived by the renderer from the Project file's `name`, `url`, `naming`, `role`, `employment`, `start`, `end` and `description`. A Project named only when its Naming is `public`; an `nda` Project renders as "NDA client".
- Role suffix, by `employment`: `contract` adds ` (Contract)`, `freelance` adds ` (Freelance)`; `full-time`, `part-time` and `independent` add nothing.
- Dates: `Mon YYYY – Mon YYYY`, the English three-letter month, an en dash with a space each side; `Present` in place of the end month when the Project has no `end`. The renderer formats `start` and `end` (`YYYY-MM`) this way. One format throughout a Version.
- Bullets: each selected Story's lead line, verbatim. A Version never rewords a Bullet; a wording that only one application needs is a Story edit or a new Story.
- Characters: no emoji; no symbols beyond `•`, `–` and `|`. Bold and italic sparingly.
- Sent PDF name: `Dolbilov_<Role>_<Company>_<MonYYYY>.pdf`, role as the posting's title in CamelCase, whichever Version it renders (general or tailored); it is the file that goes out and is not stored in the Candidate folder. The tailored source is always `version.md`. The public general Version keeps `Konstantin_Dolbilov_Resume.pdf`.
