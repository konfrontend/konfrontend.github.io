# Format rules

Rules for a rendered Version: `versions/general.md` and a tailored Version at `data/candidates/<folder>/version.md`, beside the employment Candidate's `job.md` and `cover-letter.md`. The Master is not bound. Layout (fonts, sizes, margins, spacing, single column) is fixed by `pdf-renderer/cv.css`; the Markdown shape the renderer parses is described in the `cv-pdf` skill. Adopted from upstream `resume-formatter`, which is not installed.

- Sections, in order: summary, Professional Experience, Projects. The summary is the paragraph after the contact line and carries no header. A Skills section, when a version adds one, sits between the summary and Professional Experience. Its terms are the ledger's Skills for the version's role: a term stays when a posting for the version's role would name it, and the ledger's `roles` field records that answer; the general version's role is `full-stack` (full stack developer), the frontend version's `frontend` (senior frontend developer), named by `role` in the version's frontmatter. The version groups the terms into lines and labels each; a term may be the Skill's abbreviation (RBAC, OOP) or its name without the parenthetical. The renderer fails when a term is not a ledger Skill with the role or a ledger Skill with the role is missing. No Education section. Header names come from the ATS-recognized set only.
- Contact line: location with UTC offset, email, GitHub, LinkedIn. No phone, no photo, no street address.
- Entry heading: `[Name](url) | Role (Contract) | Mar 2019 – Present`, derived by the renderer from the Project file's `name`, `url`, `role`, `employment`, `start` and `end` when the version names the Project by its slug (`### loadster`). The description line is the file's `description`. A Project with no Project file in this shape keeps its heading, description and role row written out in the version.
- Role suffix, by `employment`: `contract` adds ` (Contract)`, `freelance` adds ` (Freelance)`; `full-time`, `part-time` and `independent` add nothing.
- Dates: `Mon YYYY – Mon YYYY`, the English three-letter month, an en dash with a space each side; `Present` in place of the end month when the Project has no `end`. The renderer formats `start` and `end` (`YYYY-MM`) this way; a role row written out in the version follows the same format. One format throughout a version.
- Client and product: named only when the Project's Naming is `public`.
- Characters: no emoji; no symbols beyond `•`, `–` and `|`. Bold and italic sparingly.
- Sent PDF name: `Dolbilov_<Role>_<Company>_<MonYYYY>.pdf`, role as the posting's title in CamelCase, whichever Version it renders (general, frontend or tailored); it is the file that goes out and is not stored in the Candidate folder. The tailored source is always `version.md`. The public general version keeps `Konstantin_Dolbilov_Resume.pdf`.
