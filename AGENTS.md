# Professional profile

The professional profile of Konstantin Dolbilov, web developer, and the two things made from it: resumes and the triage of Jobs. The Profile is the source of truth; a Version and a Letter derive from it, never the other way round. `GLOSSARY.md` names the terms; use them in chat, tickets and files. Say resume, never CV.

## Folders

- `profile/`: the Profile, authored by hand. `profile.md` (identity, contact, resume order, `terms`), `voice.md`, `answers/<slug>.md`, `projects/<slug>.md` (one Project file each: meta frontmatter with the canonical `keywords`, then `## Stories` with their canonical Bullets, `## Bullets` with no Story yet, `## Notes`). `bullet-rules.md` is what a Bullet is written by; `schemas/` holds the JSON Schemas. `skills.md` is generated by `npm run build`, committed, read by nothing. `lib/` is the one Profile reader and the Profile check; it never reads `private/` or `resume/`.
- `resume/`: `versions/general.md`, the one stored Version, the Markdown twin of the public PDF; `scripts/` generates, refreshes, cuts and renders a Version. The public resume, `Konstantin_Dolbilov_Resume.pdf`, and `index.html` stay at the root for GitHub Pages.
- `autotriage/`: `catalogue/` (Flags, voice, Checks, Letter templates, the Candidate contract), `scripts/` (Guard, Verdict, the State scripts, the hooks, the Tracker, the Gap print, tests), `schemas/` (the Candidate schemas). It reads the Profile through `profile/lib/` and writes only Candidates.
- `private/`: gitignored. `candidates/<YYYY-MM-DD-slug>/` holds the Candidates: `job.md`, `letter.md`, `version.md` when the Version was tailored; `candidates/archive/` the desk Candidates, read by nothing.
- `docs/`: `format-rules.md` (what a rendered Version follows), `research/` (notes with cited sources; `resumeskills-fold-in.md` is where the folded rules come from), `agents/` (how agent skills use this repo).
- `.claude/skills/`: `route` and its States `route-intake`, `route-triage`, `route-version`, `route-proposal`, `route-verify`; `tracker` and `gaps`; `resume-version` and `resume-pdf`. `.claude/settings.json` registers the hooks, always on, and the permission allow list.

## Rules

- Scripts are TypeScript run by Node 24 directly, erasable syntax only; `tsc --noEmit` checks them. One root `package.json`, relative imports.
- A State skill's guard line prints the context or `autotriage: <state> refused …`; the skill prints a refusal verbatim and stops.
- Data follows the root, code follows the module: the Profile, the Candidates and the Versions resolve from `repoRoot()` in `profile/lib` (`CLAUDE_PROJECT_DIR`, else the repo); the catalogue, the schemas, the templates and `resume.css` from their own module. A test fixture holds data only.
- Authored content (the Profile, the Candidates, the public PDF, `index.html`) is edited by the person. Generated content (`skills.md`, a Version's sourced lines, a Bullet's rendered form) is regenerated, never hand-edited.
- A Bullet is written from its Story by `profile/bullet-rules.md` and reviewed by the person; whoever edits a Story updates its Bullets in the same edit. A wording one application needs is a Variant in that Candidate's `version.md`, never a Story edit.
- A Letter cites a Story, a Bullet, a Project's Notes or an Answer. A fact the Profile lacks is asked for once and, when confirmed, appended to the Project's `## Notes`; no State edits a Story. A Gap never enters a Letter or a Version.

## Commands

- `npm test`: every `*.test.ts`, then `tsc --noEmit`.
- `npm run build`: the Profile check, then `profile/skills.md`; run after a Profile edit and commit the result.
- `resume-version [<Candidate folder>]`: makes the general Version, or a Candidate's tailored one. `resume-pdf <Version path>`: renders it, every check PASS, one A4 page.

## Workflow for an application

`/route` with the posting pasted: intake, triage, the checkpoint (the person answers go or no-go and the Verdict is written), `route-version` on the employment route (general, or `resume-version` writes `version.md`), proposal, verify. Then `resume-pdf` on the Version sent. `/tracker` prints where every Candidate stands; `/gaps` prints the Gaps and the Skills seen.
