# Professional profile

The professional profile of Konstantin Dolbilov, web developer, and the two things built from it: resumes and the autotriage plugin. One folder per module; the Profile is the source of truth for both. `GLOSSARY.md` names the terms; use them in chat, tickets and files. Say resume, never CV.

## Folders

- `profile/`: the Profile. Authored: `profile.md` (identity, contact, resume order, the Route's settings), `voice.md`, `answers/<slug>.md`, `projects/<slug>.md` (one Project file each: frontmatter meta with canonical `keywords`, then the Stories, `- [key] Bullet` with the Facts indented beneath). Generated by `npm run build -w profile`, committed, read by nothing: `master.md` (every Story by Project, the contact line, every Skill) and `skills.md` (the Skill ledger: `shipped` Skills from the Projects' keywords, Gaps and Seen counts from the Candidates' `requirements`). `schemas/` holds the JSON Schemas; `lib/` is the one reader (`@konfrontend/profile`, TypeScript run by Node directly): parsing, validation, Story keys, `master()`, `ledger()`, `readVersion()`.
- `resume/`: `versions/general.md`, the one stored Version, a selection over the Profile (Story keys per Project, Skills lines, summary); `renderer/` renders a Version to a one-page A4 PDF through `@konfrontend/profile`. The public resume, `Konstantin_Dolbilov_Resume.pdf`, and `index.html` stay at the root for GitHub Pages.
- `autotriage/`: the Claude Code plugin, portable: it reads the Profile, takes a Job, computes a Verdict and writes a Letter; it writes only Candidates. See `autotriage/CLAUDE.md`. Enabled for every session at the repo root by `.claude/settings.json` (`extraKnownMarketplaces`, `enabledPlugins`).
- `private/`: gitignored. `candidates/<YYYY-MM-DD-slug>/` holds the Candidates (`job.md`, `letter.md` or `cover-letter.md`, `version.md` when tailored); `candidates/archive/` the desk Candidates, read by nothing.
- `docs/`: `format-rules.md` (what a rendered Version follows), `adr/` (decisions), `research/` (notes with cited sources), `agents/` (how agent skills use this repo).
- `.claude/skills/`: `resume-pdf` (render a Version), and the resumeskills skills symlinked from `.agents/skills/`, installed by the `skills` CLI (`npx skills add`, `npx skills update`), tracked in `skills-lock.json`.

## Commands

Node 24 or later. `npm install` at the root installs every workspace.

- `npm test`: the plugin and `profile/lib` tests, then `tsc --noEmit`.
- `npm run build -w profile`: regenerates `profile/master.md` and `profile/skills.md`; run it after a Profile edit or a triage and commit the result.
- `node resume/renderer/render.ts [version path]`: renders a Version; the `resume-pdf` skill wraps it.

## Workflow for an application

The employment route of the plugin: `/autotriage:route` with the posting pasted runs intake, triage, the checkpoint, `version` (general, or `--tailor` to copy `general.md` into the Candidate folder as `version.md` and edit its selection), `proposal` and `verify`. Then `resume-pdf <path to the Version>`: every check PASS, one A4 page. The resumeskills skills (`job-description-analyzer`, `resume-tailor`, `resume-bullet-writer`, `resume-quantifier`, `tech-resume-optimizer`, `resume-ats-optimizer`, `cover-letter-generator`) remain available for judgment calls on a tailored selection and its summary; a Bullet they would reword is a Story edit, never a Version edit.
