# autotriage

A plugin of the professional-profile repo (PP, the repo root two levels up). The root `AGENTS.md` describes the whole repo; this file covers the plugin.

## Agent skills

### Issue tracker

Issues live in Linear, workspace `gembag`, team `GEM`, project "Professional Profile", the same tracker as the rest of PP. See `docs/agents/issue-tracker.md`.

### Triage labels

Default five labels, names equal roles. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: the PP root `GLOSSARY.md` (`../../GLOSSARY.md`, the one glossary for the plugin and the CV) and `docs/adr/` at the PP root (`../../docs/adr/`), where the plugin's ADRs live since the merge. See `docs/agents/domain.md`.

## Plugin layout

This folder is the Claude Code plugin (`.claude-plugin/plugin.json`; `.claude-plugin/marketplace.json` is kept for the day it is ported out again as its own marketplace). `skills/<category>/<skill>/SKILL.md`, every skill listed in `plugin.json`: `route/` holds `route` (entry) and one skill per State, `profile/` holds `setup`, `skills` and `tracker`. `catalogue/` holds the portable Families, Flags, voice, verify Checks, Letter templates, the Candidate artifact contract, and the Skill ledger rules; `scripts/` the Guard, the Verdict arithmetic, the hooks, `schemas/`, and `vendor/deps.mjs` (generated by `npm run vendor`, never edited by hand); `hooks/hooks.json` registers the hooks.

The plugin holds no user data. The Profile and the Candidates live in PP's `data/` (ADR 0004; `scripts/paths.mjs` resolves it from the project the session runs in). Develop against PP with `claude --plugin-dir plugins/autotriage` from the repo root. Bump `version` in `plugin.json` on every release, or installed copies do not update.
