A **render** turns one Version into a PDF through `resume/scripts/render.ts`: the Version's Markdown is read by position, the `[slug]` and `[key]` prefixes dropped, the rest turned into HTML with `resume/scripts/resume.css`, printed by headless Chrome, then checked with Poppler and against the Profile. The script takes the input path as its first argument, relative to the repo root. A Candidate folder, `private/candidates/<folder>`, renders the Version it is sent with (its `version.md`, else `resume/versions/general.md`) into the folder as the PDF sent, `Dolbilov_<Role>_<Company>_<MonYYYY>.pdf` from the Job's `title` and `company` and the month of the render. No input, or `resume/versions/general.md`, writes `Konstantin_Dolbilov_Resume.pdf` at the repo root, the public resume. Any other Version path writes a PDF of the same base name next to itself. The script stages the HTML, the PDF and the screenshot in a fresh temporary directory, prints it, and copies the PDF to the target only when no check fails; with `--check` it writes nothing outside that directory. A render reads the Version and never edits it.

A Version is the Markdown twin of the PDF, generated by `resume-version` from the Project files (`GLOSSARY.md`): `# name`, the title, the contact line, the summary, `## Skills` lines (`Label: term, term`, every term a Keyword), then `## Professional Experience` and `## Projects` with `### [slug] Name – description`, the role row `Role | Dates`, and `- [key] Bullet` lines, canonical from the Project file, or a Variant in a tailored Version. Every sourced line equals its source in the Profile; the shape is in `docs/format-rules.md`. A Version is never hand-edited: a wrong line is fixed in the Profile and the Version regenerated (`generate.ts --refresh` on a base Version).

## Steps

1. **Prepare.** Run `npm install` at the repo root when `node_modules` is missing. The script needs Node 24, Google Chrome (override its path with `CHROME=`) and Poppler (`pdfinfo`, `pdffonts`, `pdfimages`, `pdftotext`, `pdftoppm`). Done when every tool resolves.
2. **Render.** Run `node resume/scripts/render.ts <input>` with the path the user gave the skill (`$ARGUMENTS`), or `node resume/scripts/render.ts` when they gave none. Done when the script prints one PASS, WARN or FAIL line per check, the `Screenshot:` line naming the staged page, then the `Wrote` line naming the target PDF, and exits.
3. **Look.** Read the PNG the `Screenshot:` line names, the rendered page, and show it to the user. Look for what the checks cannot see: a heading stranded at the page bottom, broken characters, a role row out of line. Done when the user has seen the page.
4. **Report.** Give the user the check lines verbatim and what you saw on the page. For each FAIL or WARN, name the cause and the fix from the table below. Done when every FAIL has a named fix and the user decides on it.

## Failures

| Check | Level | Cause | Fix |
| --- | --- | --- | --- |
| source | FAIL | The Profile does not read, or a line of the Version differs from its source: a hand edit to a heading, a role row, the contact line or a canonical Bullet. | Fix the Profile file named, or regenerate the Version (`node resume/scripts/generate.ts --refresh <input>` on a base Version; `resume-version <folder>` on a tailored one). |
| keys | FAIL | A `[slug]` with no Project file, a `[key]` no Project has, a Bullet or an entry without its prefix, or the old frontmatter shape. | Regenerate the Version with `resume-version`. |
| variants | FAIL | A base Version holds a Bullet whose text is not its canonical Bullet. | Regenerate with `--refresh`; a Variant belongs in a tailored Version only. |
| variant numbers, variant keywords | FAIL | A Variant names a number or a Keyword its canonical Bullet does not hold. | Reword the Variant in the Plan from the canonical Bullet, or drop it. |
| variant claims | WARN | A Variant is on the page; the script checks only its numbers and Keywords. | Read it against its canonical Bullet by `docs/format-rules.md`, Bullets. |
| skills terms, skills duplicates, skills labels | FAIL | A Skills term is no Keyword, a Skill appears twice, a line carries a proficiency label or a soft skill. | Fix the Skills lines in the Plan. |
| summary role noun | WARN | The summary lacks the title's last word. | Reword the summary in the Plan. |
| summary voice | WARN | The summary holds a banned phrase, an objective, trait filler or the third person. | Reword the summary in the Plan. |
| bullet length | WARN | A Bullet took more than two rendered lines (`docs/format-rules.md`). | Shorten the canonical Bullet in the Project file, or pick a Variant in a tailored Version. |
| pages | FAIL | The Version holds more than one page: a hand-added line, or a Profile edit that grew a sourced line. | Regenerate with `resume-version`; the cut drops the lowest-ranked Bullets. The font size and margins in `resume.css` stay fixed. |
| fonts intended | FAIL | Chrome substituted a missing font. | Install Georgia or Helvetica Neue on the build machine. |
| text layer, role lines | FAIL | The PDF text differs from the page, or a role title lost its dates. | Check `resume.html` in the staged directory in a browser, then `git diff resume/scripts/`. |
| reading order | FAIL | The default pdftotext mode, like a parser, reads stacked role rows as a column of titles and a column of dates. | Read `git diff resume/scripts/`; each entry renders one role row. |
| first line | FAIL | Something shares the name's line. | Read `git diff resume/scripts/`. |
| bullets | FAIL | A list lost its glyphs, or a Bullet holds a stray `•`. | Remove the stray `•` from the Bullet in the Project file, else read `git diff resume/scripts/`. |
| hyphens | FAIL | A spaced hyphen in a Bullet or the summary wrapped at the line end. | Write it as an en dash, or reword the line. |
| dates | FAIL | A Project's `start` or `end` is not `YYYY-MM`. | Fix the Project file's frontmatter. |
| characters | FAIL | A Bullet, the summary or a Skills line holds a character outside the whitelist: an emoji, a curly quote, a symbol. | Replace it in the file; `docs/format-rules.md` names the allowed ones. |
| page size, title, images, file size | FAIL | The stylesheet or the script changed. | Read `git diff resume/scripts/`. |
