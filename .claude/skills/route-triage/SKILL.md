!`node $CLAUDE_PROJECT_DIR/autotriage/scripts/guard.ts triage $ARGUMENTS`

A guard line above that starts with `autotriage:` and says `refused` is the answer: print it verbatim and stop; it names the fix.

Judgment is the model's, arithmetic is the script's. This State serves both routes. It reads the Job and the Profile, detects Flags, scores fit, picks the Family on the freelance route, and writes ids and numbers into the `verdict` block of `job.md`. The guard prints the Route, and the Route selects the Flag set: only Flags whose `routes` holds it are judged. On `route: employment` there is no Family, no budget and no money hard stop (pay is unknown until the offer), so step 3 is skipped and the block carries no `family` keys; and `verify`'s Version pass reads the `requirements` this State writes. `node $CLAUDE_PROJECT_DIR/autotriage/scripts/verdict.ts` then computes `alert_level`, `hard_stops`, and `verdict` from them; the `proposal` guard recomputes and rejects a block that disagrees, so the computed fields are never typed by hand. Everything else this State produces (evidence quotes, reasons, matched cues, safeguards) is printed for the human and thrown away; the Candidate keeps only the block. The one other field this State writes, on both routes, is `requirements` in `job.md`: the Job's required items as the posting names them. The Skill ledger derives from every Candidate's `requirements` when the Profile is built (`npm run build` at the project root), Seen counts and Gaps included; nothing is recorded here.

Inputs: `private/candidates/$ARGUMENTS/job.md` (frontmatter fields plus the posting verbatim in the body, parameter line included), `profile/profile.md` (`refused_stacks`, `identity.constraints`, `niche`, `interests`, `avoid`, `family_precedence`, `terms`, `terms.salary_floor` on employment), the Profile's Skills (the canonical names every Project file's `keywords` declare; `node $CLAUDE_PROJECT_DIR/autotriage/scripts/skills.ts match` names them), the Flag catalogue `$CLAUDE_PROJECT_DIR/autotriage/catalogue/flags.md` (Flags with cues, `scores` rubrics, `alert_level_steps`, `hard_stops`, `verdict_mapping`, the checkpoint print order), and the Family catalogue `$CLAUDE_PROJECT_DIR/autotriage/catalogue/families.md` (Families with cues, tie rule). Read all five before step 1; the catalogues are the rules, this file is the procedure.

## Steps

1. **Flags.** Walk the whole Job, parameter line and screening questions included, against every Flag in the catalogue whose `routes` holds the Candidate's route; the other route's Flags are not judged. A Flag triggers on the meaning of the cues, not on their wording: postings paraphrase. Per triggered Flag hold its id, its level, and one verbatim quote from the Job as evidence; for a stop Flag also the Profile entry it collides with (`refused_stacks`, `identity.constraints`). Green Flags in the same pass. A required stack item is one the Job names as the codebase or a must, not a nice-to-have in a preferred list. Done when every Flag of the route has been judged and each triggered one has a quote.
2. **Scores.** Judge `skill_fit`, `interest_fit`, `value` against the `scores` rubrics (`value` by the route's rubric), one line of reason each, naming the Profile entries it rests on. `skill_fit`: list the Job's required items (a must, a required skill, the existing codebase; never a preferred or nice-to-have item; technologies and domain practices only, never years of experience, spoken languages or seniority words) and run `node $CLAUDE_PROJECT_DIR/autotriage/scripts/skills.ts match "<item>" ...` with every item; the script names the canonical Skills each item names as whole words. Confirm or correct the list by reading: an item the script caught wrongly is dropped, a Skill it missed (a posting's own spelling, `Vue 3` for `Vue.js`) is added by its canonical name, and an item naming no Skill is a Gap. Hold the table: item, Skills, `shipped` or `gap`. `interest_fit`: `niche`, `interests`, `avoid`. `value`: on the freelance route the Profile `family_precedence` position of the Family from step 3 plus contract size estimated from budget, hours, and duration at Profile `terms.rate`; on the employment route the posted `salary` against Profile `terms.salary_floor`, converted to the floor's period and currency, and `3` with the reason "pay not stated" when the posting states no salary or the Profile no floor. Done when the three integers each have a rubric line they match.
3. **Family** (freelance route only; on `route: employment` skip to step 4). Pick `family` and `family_runner_up` from the Family catalogue cues, triggered Flags first; the tie rule is the Profile's `family_precedence`. Hold the matched cues and a confidence word (`clear`, `leaning`, `guess`) for the summary. Nothing fits: `family: null`, runner-up `null`. Done when both fields hold a Family id or `null`.
4. **Write the block.** First add a top-level `requirements` list before `verdict`, replacing an existing one: the required items of step 2, each a string as the posting names it (`"Vue 3"`, `"Core Web Vitals"`), nice-to-haves left out. Then, with the Edit tool, add the `verdict` block as the last key of the `job.md` frontmatter, replacing an existing one: `family`, `family_runner_up` (freelance route only; absent on `route: employment`), `flags` (every triggered id, green and stop included), `skill_fit`, `interest_fit`, `value`, then the placeholders `alert_level: 1`, `hard_stops: []`, `verdict: ask`, `decision: null`. The write hook validates against the route's schema (`$CLAUDE_PROJECT_DIR/autotriage/schemas/job-freelance.schema.json` or `job-employment.schema.json`) and blocks with the error list on mismatch: fix and write again. Then run `node $CLAUDE_PROJECT_DIR/autotriage/scripts/verdict.ts $ARGUMENTS`; it rewrites the three computed fields and prints them. Done when the script has printed `alert_level`, `hard_stops`, `verdict`, and `requirements` is in `job.md`.
5. **Summary.** Print one screen in the order the Flag catalogue fixes under "What the human sees first": the verdict line (verdict, Alert Level, Family with runner-up and confidence on the freelance route, three scores), hard stops, each triggered Flag as `id (level N): "quote"`, green Flags, the safeguards the Letter will state (the `safeguard` of every triggered risk Flag whose safeguard is not `none`, with its `slot`), a "Skills" block (one line per Job item as `item -> Skill` or `item -> gap`), and one closing line: why `ask`, or why not the neighbouring verdict. Add the posted budget against the Profile rate when the Job is `fixed` or hourly below `terms.rate`, so the human sees the money before answering; on the employment route add the posted salary, or "pay not stated". Done when every triggered Flag and every hard stop appears on the screen.
6. **Checkpoint.** Ask the human for `go` or `no-go` and wait. A correction instead (a Flag to add or drop, a score, the Family): apply it, redo steps 4 and 5, ask again. Write the answer into `verdict.decision` with the Edit tool. Done when `decision` is `go` or `no-go`.
7. **Hand off.** On `go`: invoke `route-proposal $ARGUMENTS` with the Skill tool on the freelance route, `route-version $ARGUMENTS` on the employment route, no further question. On `no-go`: one line saying the Route has ended for this Candidate.
