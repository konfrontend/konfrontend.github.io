!`node ${CLAUDE_PROJECT_DIR:-$(git rev-parse --show-toplevel)}/autotriage/scripts/guard.ts triage $ARGUMENTS`

A guard line above that starts with `autotriage:` and says `refused` is the answer: print it verbatim and stop; it names the fix.

Judgment is the model's, arithmetic is the script's. This State serves both routes. It reads the Job and the Profile, detects Flags, scores fit, lets the script compute the Alert Level, the hard stops and its recommendation, prints one screen, and waits for the human. Nothing is written before the human answers: the scores, the evidence, the Safeguards and the recommendation are session output and are thrown away. At the Checkpoint it writes the Verdict into `job.md`, on go and on no-go alike, with `requirements` and, on the freelance route, `flags` (`autotriage/catalogue/candidate-artifacts.md`). The guard prints the Route, and the Route selects the Flag set: only Flags whose `routes` holds it are judged. No route has a money hard stop: a posted budget or rate is a line on the summary screen. On `route: employment` there is no budget (pay is unknown until the offer), and no Flag has a Safeguard Slot, so `flags` is not stored.

Inputs: `private/candidates/$ARGUMENTS/job.md` (the identity fields plus the posting verbatim in the body, parameter line included: the budget, the hours, the salary and the remote policy are read from the body), `profile/profile.md` (`identity.constraints`, `terms`, `terms.salary_floor` on employment), the Profile's Skills (the canonical names every Project file's `keywords` declare, and the claimed Skills in `profile/profile.md` `skills.claimed`; `node ${CLAUDE_PROJECT_DIR:-$(git rev-parse --show-toplevel)}/autotriage/scripts/skills.ts match` names both), and the Flag catalogue `autotriage/catalogue/flags.md` (Flags with cues, `scores` rubrics, `alert_level_steps`, `hard_stops`, `verdict_mapping`, `checkpoint_fields`, the print order). Read all four before step 1; the catalogue is the rules, this file is the procedure.

## Steps

1. **Flags.** First read every document the posting links (a requirements PDF, a brief, a spec): it is part of the Job, and it can change the Flags and the scores. One that cannot be opened: ask the person to paste it, and wait. Then walk the whole Job, parameter line and screening questions included, against every Flag in the catalogue whose `routes` holds the Candidate's route; the other route's Flags are not judged. A Flag triggers on the meaning of the cues, not on their wording: postings paraphrase. Per triggered Flag hold its id, its level, and one verbatim quote from the Job as evidence; for the stop Flag also the Profile constraint it collides with (`identity.constraints`). Green Flags in the same pass. Done when every linked document has been read, every Flag of the route has been judged and each triggered one has a quote.
2. **Scores.** Judge `skill_fit` and `value` against the `scores` rubrics (`value` by the route's rubric), one line of reason each, naming the Profile entries it rests on. `skill_fit`: list the Job's required items (a must, a required skill, the existing codebase; cues `must have`, `required`, `essential`, a `Requirements` list; never a preferred or nice-to-have item, cues `nice to have`, `bonus`, `preferred`, `ideally`, `a plus`; technologies and domain practices only, never years of experience, spoken languages, degrees or seniority words) and run `node ${CLAUDE_PROJECT_DIR:-$(git rev-parse --show-toplevel)}/autotriage/scripts/skills.ts match "<item>" ...` with every item; the script names the canonical Skills each item names as whole words, a claimed Skill marked `(claimed)`. Confirm or correct the list by reading: an item the script caught wrongly is dropped, a Skill it missed (a posting's own spelling, `Vue 3` for `Vue.js`) is added by its canonical name, and an item naming no Skill is a Gap, spelled as the posting spells it. When the posting bundles several roles, the core role's items come first and count; the rest are other duties. Hold the table: item, Skills, `shipped`, `claimed` or `gap`. A `claimed` item is covered for `skill_fit` the same way a `shipped` one is, and is never a Gap. `value`: on the freelance route the contract size estimated from budget, hours, and duration at Profile `terms.rate`, plus `paid-first-milestone`; on the employment route the posted salary against Profile `terms.salary_floor`, converted to the floor's period and currency, and `3` with the reason "pay not stated" when the posting states no salary or the Profile no floor. Done when both integers have a rubric line they match.
3. **Arithmetic.** Run `node ${CLAUDE_PROJECT_DIR:-$(git rev-parse --show-toplevel)}/autotriage/scripts/verdict.ts --route <route> --skill-fit <n> --flags <id,id>`. It prints `alert_level`, `hard_stops` and its recommendation (`go`, `no-go`, `ask`) and reads no Candidate file. Done when the three values are in hand.
4. **Summary.** Print one screen in the order the Flag catalogue fixes under "What the human sees first": the recommendation line (recommendation, Alert Level, two scores), hard stops, each triggered Flag as `id (level N): "quote"`, green Flags, the Safeguards the Letter will state on the freelance route (the `safeguard` of every triggered risk Flag whose safeguard is not `none`, with its `slot`), a "Skills" block (one line per Job item as `item -> Skill`, `item -> Skill (claimed)` or `item -> gap`), and one closing line: why `ask`, or why not the neighbouring recommendation. Add the posted budget against the Profile rate when the Job is fixed-price or hourly below `terms.rate`, so the human sees the money before answering; on the employment route add the posted salary, or "pay not stated". Done when every triggered Flag and every hard stop appears on the screen.
5. **Checkpoint.** Ask the human for `go` or `no-go` and wait. A correction instead (a Flag to add or drop, a score, an item of the Skills table): apply it, redo steps 3 and 4, ask again. Then write the Checkpoint fields with `node ${CLAUDE_PROJECT_DIR:-$(git rev-parse --show-toplevel)}/autotriage/scripts/verdict.ts write $ARGUMENTS --verdict <go|no-go> --requirements "<item>,<item>"`, adding `--flags <id,id>` on the freelance route (`--flags ""` when none triggered; the script refuses a freelance Checkpoint without it): `verdict` is the human's answer, `requirements` the required items of step 2, each in the Keyword's spelling where a proved Skill matched, the claimed Skill's where a claimed one did, and the posting's otherwise, nice-to-haves left out, `flags` every triggered id, green and stop included. The script replaces earlier Checkpoint fields and refuses before writing when the result would be invalid: fix the named field and run it again. If the human never answers, nothing is written. Done when `verdict` is in `job.md`.
6. **Hand off.** On `go`: invoke `route-proposal $ARGUMENTS` with the Skill tool on the freelance route, `route-version $ARGUMENTS` on the employment route, no further question. On `no-go`: one line saying the Route has ended for this Candidate.
